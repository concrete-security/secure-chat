# AGENTS.md – Guidance for Automated Coding Agents

## 1. Overview

This repository hosts three logical parts:

* **cvm** – Docker‑compose services (`auth-service`, `cert‑manager`, `attestation‑service`, …) with a Python‑based test harness.
* **frontend** – A Next.js / TypeScript UI.
* **scripts** – Small helper utilities used by CI and local development.

The file is a single source of truth for agents that need to **build**, **lint**, **test**, or **modify** the codebase.

---

## 2. Build / Run Commands

| Goal | Command | Notes |
|------|---------|-------|
| Full dev workflow (containers + all tests) | `make dev-full` | Builds images, spins services, runs every test suite, then tears down. |
| Start services (dev) | `make dev-up` | Uses `docker‑compose.dev.override.yml`. |
| Stop services (dev) | `make dev-down` | Stops containers started by `dev-up`. |
| Build Docker images only | `make docker-build` | No containers are started. |
| Run a subset of services | `make docker-up SERVICES="auth-service cert-manager"` | Starts only the listed services. |
| View logs for all services | `make docker-logs` | Tail logs with timestamps. |
| Front‑end dev server | `pnpm dev` (or `make dev`) | Hot‑reloading Next.js server. |
| Front‑end production build | `pnpm build && pnpm start` | Optimized static assets then serve. |

## 3. Linting & Formatting

### Python (cvm)
* **Tool:** `ruff` (configured in `cvm/auth-service/pyproject.toml`).
* Static analysis: `ruff check .`
* Auto‑formatting: `ruff format .`
* Key settings – line length **100**, double‑quoted strings, 4‑space indent.

### TypeScript / JavaScript (frontend)
* **Tool:** `pnpm lint` (ESLint + Prettier).
* Formatter: `pnpm format` (Prettier).
* Enforced style – 2‑space indent, double quotes, trailing commas, max line length **100**.

## 5. Code‑Style Guidelines

### 5.1 Imports
#### Python
1. Standard‑library imports first, alphabetical.
2. Third‑party imports next, alphabetical.
3. Local project imports last.
4. One import per line, no `from module import a, b`.
5. Use absolute imports; avoid relative imports beyond the repository root.

```python
import os
import sys

import requests
from fastapi import FastAPI

from auth_service.main import main
```

#### TypeScript
* Order: built‑ins → external packages → internal aliases (`@/`).
* One import per line; prefer named imports.

```ts
import { readFileSync } from "fs";
import axios from "axios";
import { createClient } from "@/lib/supabase/client";
```

### 5.2 Formatting
* **Python:** 4 spaces, no tabs, trailing commas for multi‑line collections, double quotes for strings.
* **TypeScript:** 2 spaces, double quotes, semicolons, Prettier‑enforced layout.
* Run `ruff format .` and `pnpm format` before committing.

### 5.3 Types & Annotations
* **Python:** Full PEP 484 hints for public APIs. Prefer built‑in generics (`list[str]`, `dict[str, int]`).
* **TypeScript:** `strict` mode enabled; always annotate parameters and return types. Use `unknown` for external JSON before narrowing.

```python
def hash_token(token: str) -> bytes:
    """Hash a token using SHA‑256."""
    return hashlib.sha256(AUTH_SALT + token.encode()).digest()
```

```ts
export function getUser(id: string): Promise<User> {
  return supabase.from<User>("users").select().eq("id", id).single();
}
```

### 5.4 Naming Conventions
| Entity | Convention |
|--------|------------|
| Python modules/files | `snake_case.py` |
| Python packages | `snake_case` |
| Classes (both languages) | `PascalCase` |
| Functions / methods | `snake_case` |
| Constants | `UPPER_SNAKE_CASE` |
| Variables | `snake_case` |
| Test functions | `test_<description>` |
| React components | `PascalCase` (file name kebab‑case) |
| Hooks | `use<Pascal>` |

### 5.5 Error Handling & Logging
* Raise specific built‑in exceptions (`ValueError`, `RuntimeError`) or custom subclasses.
* Do **not** swallow exceptions; unexpected errors should be logged with `logger.exception`.
* HTTP endpoints must return appropriate status codes and JSON error bodies.
* Never log secrets or authentication tokens.

### 5.6 Documentation
* **Python:** Google‑style docstrings (configured via ruff). Include `Args:` and `Returns:` sections.
* **TypeScript:** JSDoc comments with `@param` and `@returns`.
